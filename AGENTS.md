## Project purpose

pi-onboard is a Pi extension that helps users onboard into unfamiliar repositories. Running `/onboard` triggers a quick static discovery pass, then fills the editor with a structured prompt for the AI agent to analyze the repo and generate durable onboarding artifacts (AGENTS.md + an interactive HTML overview served over HTTP).

## Tech stack

- TypeScript (loaded directly by Pi via jiti — no build step)
- Node.js built-ins only (`node:http`, `node:os`, `node:crypto`, `node:fs`) — zero runtime dependencies
- Pi Extension API (`@earendil-works/pi-coding-agent` as peer dependency)

## Important paths

- `extensions/index.ts` — Entry point: registers `/onboard` command, orchestrates discovery → server → prompt
- `extensions/prompt-template.md` — The structured prompt template sent to the agent
- `extensions/discovery.ts` — Static repo scanner (manifests, README, directories, languages)
- `extensions/server.ts` — HTTP server with idle lifecycle, 0.0.0.0 binding, UUID token URLs
- `extensions/flags.ts` — Flag parsing and tab-completion
- `extensions/types.ts` — Shared TypeScript types
- `docs/` — Design docs and research findings

## Commands

- There are no npm scripts — the extension is loaded directly by Pi via `-e .` or `pi install`

## Working conventions

- **No build step.** TypeScript is loaded directly by Pi's jiti runtime.
- **No runtime dependencies.** Only Node.js built-ins are used.
- **Prompt-driven architecture.** The extension's job is discovery + server + prompt construction; the AI agent does the actual analysis and file writing.
- **File safety.** Existing files trigger `.draft` variants unless `--force` is used.

## Where to start when making changes

1. Read `extensions/index.ts` — the command handler and prompt builder
2. Read `extensions/prompt-template.md` — the template the agent receives
3. Check `extensions/server.ts` — the HTTP server lifecycle
4. Read `docs/DESIGN.md` — full design rationale
